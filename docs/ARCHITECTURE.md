# Architecture

`src/cli/bin.ts` is a thin executable with SIGINT/SIGTERM handling. `main.ts` owns commands, structured stdout and exit codes. Input/environment errors are code 2, executed assertion failures code 1, passes code 0. Browser launch/tool failures still generate a result with status `error` when an artifact directory is writable. Invalid input is rejected before a run exists. A filesystem failure may prevent report writing and returns code 2.

`config/schema.ts` defines strict Zod v4 discriminated steps. `load.ts` bounds and parses YAML, computes SHA-256 and resolves environment references separately. Nothing executes user-derived code. Unknown fields fail closed.

`engine/run.ts` exposes `runJourney(options)` independently of stdout and CLI parsing. It creates one Chromium context, installs request policies and listeners, then executes ordered steps through `steps.ts`. Failed steps record a reason and leave subsequent steps skipped. `expectResponse` installs the response wait before its associated click, checks method/path first, then compares the actual status. The promise handlers attach together so immediate responses and rejection timing are deterministic.

`evidence/store.ts` handles private directories, bounded reads and atomic writes. `trace.ts` strips network/resource content from the Playwright archive rather than exporting a raw trace. This consciously limits replay features. `report/write.ts` validates result objects and checks artifact existence; `render.ts` renders escaped standalone HTML with zero scripts and a restrictive CSP. Missing captures are labeled unavailable.

The library entry `src/index.ts` exports schema, parser, loader, runner, result types and MCP server factory. Adapters call these services directly. Metadata includes version, Node, Chromium, origin hostname, source basename and checksum, time and duration; no environment inventory. Reproduction commands include only flow path and target origin, shell-quoted without resolved credential values.

The admissions fixture uses Node's built-in HTTP module instead of Express/Vite: the application is small enough to avoid another runtime dependency, and no bundler or database is needed. This is the documented layout/technology adjustment. Its single officer role is checked via an in-memory session before listing, creating, viewing or approving records. A server startup flag changes only approval to HTTP 500. Restarting resets its state.

Tests: Vitest unit plus integration tests instrument all core `src/**/*.ts` (including engine, config, evidence, report and CLI implementation). Only the executable trampoline and export-only barrel are excluded. Integration tests launch Chromium to cover real engine branches. Playwright E2E separately tests built CLI processes and both fixture modes. `scripts/package-smoke.mjs` verifies the installed tarball's executable. The engine is not mocked in acceptance tests.

Build uses tsup to emit ESM with the original executable shebang and external runtime dependencies and TypeScript declarations; the bin is chmod 0755. A files whitelist limits local tarballs. Root remains `private: true` with `license: "Apache-2.0"` and no `mcpName`. LICENSE and NOTICE are required package assets and fingerprinted validation inputs. Source licensing grants no release-workflow publication authorization. The pinned minimatch 11.0.1 override patches the development toolchain's glob dependency; lint, tests and packaging must pass against it.

Upstream API references checked during implementation: [Playwright tracing](https://playwright.dev/docs/api/class-tracing), [Zod strict objects](https://zod.dev/api), [Vitest coverage](https://vitest.dev/guide/coverage). Exact installed compatibility is recorded in the lockfile and checked by `npm ci`.

## Local MCP adapter

`mcp/server.ts` registers eight tools using SDK v2. Both CLI and MCP call the existing loader, `runJourney()` and doctor logic. Saved report retrieval validates `runSchema` and uses the same bounded file/run-directory helpers; there is no shell-spawned CLI or duplicate Playwright runner. The doctor service retains its CLI module location for compatibility and gains an optional browser-check switch whose default preserves existing CLI behavior.

`mcp/stdio.ts` owns SDK `serveStdio`, protocol-era selection, bounded input transport, cancellation and final cleanup. The async factory is exported for in-memory SDK-client tests; actual executable and packed-executable tests cover stdio too. Diagnostics go only to stderr. `policy.ts` fixes canonical workspace/approved flow roots and numeric loopback scope at startup. `schemas.ts` combines strict Zod schemas with a Standard Schema validation wrapper that hides attacker-supplied keys in SDK errors. `serialization.ts` validates and bounds results; `adapters.ts` maps existing saved-run evidence into factual, page-text-free summaries. One browser operation runs per server; shutdown waits for engine cleanup.

MCP enables `engine/origin-guard.ts`, a Chromium Fetch interceptor installed before primary-page navigation, checking redirected requests as well as initial URLs. The library option defaults off to preserve existing CLI routing behavior. Same-origin normal redirects, including fixture login/create 303 responses, remain real and unchanged. No application HTML/HTTP responses are mocked by the guard. Security tests prove denied single/chained redirect destinations receive zero requests.

The portable skill is bundled under `skills/journeyproof`, with host installation remaining explicit. Coverage includes all new MCP and engine modules; exclusion rules/thresholds remain unchanged. `test:mcp` and `test:skill` are independently runnable and both suites are included in `test:coverage`, which the main CI pipeline runs once. CI additionally exercises real built stdio healthy/broken journeys and installs/tests the local tarball, comparing advertised schemas with the checked-in documentation snapshot.

## Observations and maps

The same engine adds optional `observations.json` v1 without changing run.json v1 or original MCP contracts. `observations/capture.ts` coordinates bounded navigation/step/popup events; `anchors.ts` is a fixed pure DOM read tested in real Chromium. Capture never activates links/forms or executes page-derived code. `map/normalize.ts` strips secrets/query data, preserves exact keys and merges only explicit hints. `build.ts` and `compare.ts` consume sanitized saved data deterministically, preserving action-level and per-run provenance. MapService/storage enforce fixed artifact names, bounded regular files and canonical paths, and export private portable evidence excerpts. CLI and the two new MCP tools use this same service.

The viewer reuses the existing static-report approach rather than adding a production React/Vite stack. SVG edges and DOM buttons render from embedded escaped JSON; a self-contained compiled browser function and CSS have exact CSP hashes. No runtime fetch or external assets. File:// and copied folders work offline. All viewer interactions are read-only. Vitest's matching browser-playwright development provider executes that exact viewer function and DOM reader for merged V8 coverage; Playwright E2E additionally validates the built exported HTML against real runs. The pre-existing exclusions/thresholds remain unchanged. [Contracts](MAP_SCHEMA.md), [threat model](MAP_SECURITY.md).
