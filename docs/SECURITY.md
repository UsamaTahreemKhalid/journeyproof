# Security model

JourneyProof executes explicit browser actions against a target the operator is authorized to test. YAML, page content and stored report text are untrusted. The operator, local filesystem, configured environment and installed dependencies are trusted. This is not an OS sandbox for hostile sites. Never supply production credentials or test someone else's website without authorization.

## Credentials and evidence

Secrets are read only from explicitly named environment variables; literal `value` is for nonsensitive test data. Names are reported for missing variables, never their values. Every resolved value is redacted from structured reports and browser error text, including URL-encoded occurrences. URL queries/fragments and embedded URL credentials are removed. The engine never exports storage state, local storage, cookies, authorization headers or request/response bodies.

Failure screenshots mask inputs, textareas, editable content, environment-filled locators and text matching known secret values. Other application data can remain visible. Encoded/transformed secrets, secrets rendered into images, canvas content and unexpected page content are not guaranteed to be masked. Synthetic data only is the supported use case. Screenshots and traces must be reviewed manually before sharing.

Playwright traces start with screenshots, DOM snapshots and sources disabled. On save, the sanitizer retains operation `.trace` records, removes console/event/input records, removes action text/value arguments, redacts configured secrets/queries, and supplies empty `.network` records. It excludes all resources, sources and payloads. This sacrifices DOM replay, network inspection and filmstrip in Trace Viewer; JSON/HTML supply safe HTTP metadata. The raw archive exists briefly inside a private run directory and is removed in `finally`. A hard process kill or disk error can leave raw intermediate files: remove the run directory before sharing. No uploads or telemetry are enabled.

## Navigation and bounds

Strict Zod objects and bounded YAML parsing reject tags, aliases, anchors, duplicate keys/IDs, unknown actions/fields and unsafe paths. YAML cannot provide scripts, shell commands, XPath, CSS or regular expressions. Browser locators and path matching are constrained. Page JavaScript still executes as in any browser and is not inherently trustworthy.

CLI, SDK, MCP and generated regressions use the same mandatory Chromium origin guard before the first application navigation. The approved origin is the normalized HTTP(S) scheme, hostname and port selected at startup; URL credentials are rejected. Same-origin navigation, SPA history changes and relative/same-origin HTTP redirects remain supported. Chromium Fetch pauses redirect hops natively; document 301/302/303/307/308 responses also have their Location checked before continuation. There is no request proxy, manual redirect following or replay of POST/PUT/PATCH data. Destination-server counters test forbidden requests, rather than treating a failed journey as proof of prevention.

Cross-origin document requests, script/anchor/meta-refresh navigation, and iframe navigation are denied before dispatch in the tested Chromium paths. Context routing blocks every extra page's first request, including a same-origin popup that could otherwise redirect before a page handler attaches; extra pages are also closed and fail their affected step, including blank or same-origin popups (`EXTRA_PAGE_BLOCKED_BEFORE_REQUEST`). The existing resource policy remains **same-origin only** for images, fonts, scripts, stylesheets and browser fetch/XHR. There is no cross-origin resource/API/navigation allowlist. WebSockets are closed and Service Workers are blocked; frame-less requests fail closed. Applications depending on these features are outside this runner's supported compatibility policy. `--allow-remote`/SDK `allowRemote` acknowledges only the initial target, never additional destinations; use a separately authorized run to select another origin. MCP/generated execution still accepts numeric loopback only.

Interception setup/command/session failure closes the context without a routing-only fallback. The deprecated SDK `guardRedirectOrigins:true` is accepted; `false` or other supplied values are rejected before browser launch. A blocked document sets optional `run.security.code`, fails its affected step and retains sanitized JSON/HTML evidence. `ORIGIN_BLOCKED_BEFORE_REQUEST` and `REDIRECT_DENIED_BEFORE_REQUEST` describe policy blocking; `INTERCEPTION_UNAVAILABLE` is a setup/runtime infrastructure failure. `BROWSER_NAVIGATION_FAILED` records native browser failure (for example an invalid redirect Chromium rejects before exposing headers), and `NAVIGATION_DENIED_AFTER_COMMIT` is a fallback detection of a non-approved document commit. Neither latter code proves pre-request isolation. Timeouts, cancellation and application assertion/HTTP failures retain their existing status/reason semantics. MCP uses fixed security messages without destination URLs, queries or credential values.

Only the existing Chromium runner is supported. Firefox/WebKit do not provide this CDP guard and are not interchangeable security fallbacks. Downloads are canceled. This is not complete browser-network isolation, an OS firewall, DNS-rebinding protection, or protection against browser exploits. Browser-managed connections, DNS/preconnect, native software, arbitrary SDK callbacks and server-side requests made by the application are outside the tested document boundary. Use trusted disposable synthetic targets and OS egress controls for hostile content. Redaction and screenshots still require manual review.

Limits: 128 KiB journey, 100 steps, 500-character locator/name/path strings, 2000-character fill values, 30 seconds per step, five minutes per run, one page, 200 HTTP events, 100 errors, 100 warnings, 3000 chars per browser diagnostic, 4 MiB screenshot and 12 MiB retained trace. Large captures are omitted with warnings. These bound retained artifacts, not the full memory/network consumption of a hostile browser application. Browser cleanup runs after success/failure/interruption. Abrupt SIGKILL cannot run cleanup.

## Local files and reports

Default evidence is ignored `.journeyproof/runs/<timestamp-random>/`. New directories use 0700 and written files 0600 on POSIX, respecting stricter umask. Existing parent-directory permissions are the operator's responsibility. Output IDs use a strict grammar; symlink run directories, traversal IDs, symlink JSON and oversized JSON are rejected. Report links are restricted to fixed artifact filenames. Report text is escaped, scripts are absent, CSP denies external resources and base URLs. Inline CSS is the intentional standalone-report styling exception. Report files never request CDNs, fonts or scripts.

Retention is manual: remove old ignored run directories when no longer needed. No automatic upload exists, including in CI. CI tests generate only fictional demo evidence and do not upload developer runs. Use local disk encryption if other local administrators are a concern.

## Fixture and reporting

The demo binds only to 127.0.0.1, uses an in-memory single fictional officer session with HttpOnly/SameSite=Strict cookie and fictional applicant records. Restart resets admissions and sessions. It has no production security guarantees, session expiry, durable storage, account management or deployment support.

For a suspected vulnerability, follow the [private reporting policy](../SECURITY.md). Do not post credentials, unreviewed traces or sensitive screenshots in an issue. Include a synthetic reproduction and affected versions. The root policy defines the reporting channel and best-effort response expectations; this document describes implementation boundaries.

## MCP threat model

The local agent host is a new trust boundary. Tool arguments, YAML files, persisted reports, filenames, page text and logs are untrusted. Only register this server in a workspace and against a local application you are authorized to mutate.

- **Prompt injection:** MCP summaries omit application HTML, console logs, locators, flow names and arbitrary browser diagnostics. Tool input errors use fixed messages so malicious unknown keys are not echoed by SDK validation. Step tokens and bounded HTTP metadata are data with `untrustedData:true`; the skill explicitly forbids treating them as instructions. This reduces attack surface but cannot make a model immune to all malicious filenames/metadata.
- **Malicious journeys:** the existing strict YAML parser rejects unknown schema versions, executable actions, aliases/tags, huge files and unsupported locators. Tool validation never resolves env values or launches a browser. A run executes only the selected file under an operator-approved folder. This is directory-level authorization; the operator must review the selected flow and configure host permissions. An agent with separate write tools can change that file. MCP cannot prove user intent or provide per-file cryptographic approval.
- **Filesystem escape:** canonical workspace is fixed at startup, approved flow folder is startup-only, tool paths are relative and bounded, every component is checked, symlinks (even internal ones), hidden flow components, absolute paths and traversal are refused. Reports accept a strict run ID only, from fixed `.journeyproof/runs`; report-file symlinks and mismatched IDs are rejected. Missing output ancestors are checked before creation, including a symlinked `.journeyproof` parent. Files retain private permissions. These checks are not an OS sandbox: a concurrent hostile local user can race path checks or modify already trusted workspace files; use separate OS accounts/containers for hostile users.
- **SSRF and network scope:** MCP disables remote execution altogether, even when `allowRemote:true`. Only normalized HTTP(S) origins with hostname exactly numeric `127.0.0.1` or `[::1]` are accepted. `localhost` and DNS names are rejected, avoiding target DNS re-resolution/rebinding. Same-origin routing, blocked WebSockets/service workers, one-page policy and blocked downloads remain. The shared runner requires Chromium DevTools Fetch interception before primary-page navigation to check every redirect hop, because normal Playwright routing visits only the original request. Tests send direct and chained redirects to a harmless second origin and assert zero requests reached it. See [Playwright redirect routing behavior](https://playwright.dev/docs/network).
- **Browser side effects:** actions can submit forms and change app state. Run annotations are non-read-only, non-idempotent and potentially destructive. Numeric loopback includes potentially sensitive local services; startup workspace trust and host/user selection matter. This is not a complete browser/network sandbox: browser-internal traffic, OS networking, hostile native software and arbitrary capabilities of local application servers are not comprehensively isolated. Extra pages are immediately closed; the mandatory Fetch guard attaches to the selected primary page and context routing denies extra-page requests before dispatch. For hostile sites use OS egress controls. No remote-target security guarantee is claimed. The CLI's separate explicit remote opt-in remains unchanged; MCP never enables it.
- **Secrets and evidence:** credentials are externally inherited env references, never password tool arguments. No `.env` loading, headers, cookies or bodies are exposed. The engine redacts referenced values in JSON/HTML/trace and masks failure screenshots as before. MCP sends only allowlisted metadata and evidence locations, never binary captures or raw page/log text. Redaction is not a guarantee for transformed secrets or arbitrary image/application data; do not use production credentials. Tool paths/IDs are not a channel for retrieving env values. Saved reports from prior CLI runs must already follow the same evidence policy.
- **Resource limits/cancellation:** strict tools cap inputs, discovery (500 entries, depth five, 50 results), steps (100), events (50 returned), summaries (22 KB), payload (24 KB before text duplication), and stdio messages (64 KiB). One run/browser doctor per server, <=30 seconds per step, <=5 minutes per run. Cancellation, protocol EOF and SIGINT/SIGTERM abort the engine; cleanup runs in finally. Doctor probes have a bounded launch timeout. Multiple server processes are not globally coordinated; file sizes and raw trace/browser work can grow before retained-artifact limits apply. SIGKILL/disk failures can leave intermediate files.
- **Retention/local access:** no HTTP server, uploads, analytics, hosted AI, public registry or automatic cleanup. Artifacts remain until manually removed and can be read by local principals with filesystem access. MCP report retrieval exposes bounded metadata to the connected agent host; if that host uses a hosted model, that metadata may be sent by the host to its provider. Screenshots/traces are never attached automatically. Treat host registration as granting the documented local capability, and review host/model privacy settings.

## Map boundary

Maps add offline artifact reads/writes, passive bounded observations and a static viewer. The same runner still owns all intentional actions; passive discovery never follows anchors. Original MCP execution restrictions and five tool contracts remain unchanged. See [map security](MAP_SECURITY.md) for path confinement, role/non-coverage semantics, CSP/injection defenses, masking/trace-result minimization, bounded output, legacy evidence policy and local-writer/retention risks. No remote uploads or registry submissions were added.

## Regression source and execution

Generation is offline, bounded and limited to approved YAML or linked saved runs. The v1 IR rejects literal fill values and embedded origins; every fill becomes a required environment reference. Common private labels/assertions block output entirely. This is not a universal PII classifier: review source definitions. Strict JSON literal serialization prevents source injection from quotes, template markers, shell syntax, controls, Unicode or script delimiters. No data-derived eval, shell command or MCP execution API exists.

Only workspace-relative tests/generated spec/draft paths are writable. Every existing component is checked for symlinks. Dry runs create nothing. New files use atomic no-overwrite create; CLI force uses atomic replacement; MCP never exposes force. Private temporary files are cleaned up. Concurrent hostile directory replacement is outside the trusted-filesystem threat model. Source linkage/checksums establish consistency, not tamper-proof attestations. Legacy reports remain readable but need a fresh linked run for verified generation.

Generated tests use the existing origin-guarded engine, numeric-loopback fixtures only, required inputs, redacted reports, masked screenshots and sanitized traces. Native runner traces/screenshots/video are disabled. Generated callback exceptions retain only fixed action messages or numeric HTTP mismatch, with raw causes omitted intentionally. Reporter JSON is inspected in memory and discarded by the demo harness. Ordinary browser/page error text and unexpected screenshots can still contain unknown private data; synthetic fixtures and manual review remain required. Inputs shorter than three characters or overlapping status words are rejected by the new runtime to avoid corrupting evidence under substring redaction. CI uploads remain disabled. See [generation limits](REGRESSION_GENERATION.md) and the release boundaries below.

## Release threat model and regression gates

Trusted: operator-owned source, dependencies/environment, local filesystem and explicit synthetic fixture authorization. Untrusted: YAML, URLs, page/DOM/error/HTTP strings, stored artifacts, generated source preview and package manifests. Assets are data, never agent instructions. The tool is not an OS sandbox or a universal data-loss prevention system.

| Boundary / threat      | Protection and executed regression                                                                                                                                                                                                                      |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Shell/source injection | Node executable + argument arrays, shell disabled; JSON-literal codegen and hostile string/AST tests; no MCP CLI shellout or arbitrary JS action                                                                                                        |
| Workspace/SSRF         | existing traversal/symlink/ID bounds, startup approved roots, numeric loopback MCP/generated targets and per-hop redirect interception; cloud-metadata and chained-redirect tests remain                                                                |
| Private data in output | environment-backed fills, bounded sanitized reports/observations/traces, masked PNG, fixed MCP error envelopes; unknown YAML field names no longer echoed into CLI errors; installed fixture tests inspect code/reports/maps/trace text/reporter output |
| Prompt/HTML injection  | page text never becomes instructions, dynamic labels escaped, CSP hashes and fixed evidence links; earlier injection/browser tests retained                                                                                                             |
| Package leakage        | actual dry/real manifest equality, explicit narrow runtime/docs/demo/Skill allowlist, forbidden paths/history/artifacts/.env rejection, known token/private-key/machine-path scan and file/total size limits; internal engineering reports excluded     |
| Release privilege      | private state and absent mcpName guards, Apache-2.0 licensing without publication approval, script/workflow publication checks, no privileged PR trigger/OIDC write/upload; draft publish plan outside executable workflows                             |
| Resource failure       | existing step/run deadlines and capture bounds, unique synthetic workspace/ports, readiness + finally teardown, child timeout, one regression worker/zero retries; missing runtime dependency negative proves no hidden checkout fallback               |

No runtime telemetry, auto-update, external AI API or artifact upload. Package/dependency installation, browser downloads and dependency audit can use external registries; offline viewing/runtime is distinct from offline installation. Curated docs PNGs were visually reviewed from actual installed synthetic runs; binary pixel content cannot be certified by token regexes. Keep manual review for arbitrary app screenshots, transformed secrets, images/canvas, local-writer races, hard kills and storage exhaustion across indefinitely retained runs. Retention remains operator-owned; default package checks remove temp installs, explicit --keep retains evidence.

Run `npm run release:check` to record the current dependency advisory result and validation evidence locally under the ignored `.journeyproof/release-check/` directory. An audit is a time-limited registry advisory check, not proof of security. No invasive upgrade or relaxed threshold was used. The release gate scans known credential formats and personal machine paths; it cannot identify all secrets. Workflow guards are conservative regression checks over trusted repository configuration, not a sandbox for arbitrary malicious workflow code.
